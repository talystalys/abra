## 2. Independent Fact Demarcation

In accordance with experimental discipline, we distinguish two separate and independent facts:

### Fact A: Local Invocation Permission Constraint
The immediate local invocation failure is `ERR_NVGPUCTRPERM`. Modern NVIDIA drivers (550.x) restrict non-root hardware performance counter access by default. In accordance with the non-modification security rules of the research contract, kernel module parameters (`NVreg_RestrictProfilingToAdminUsers=0`) and root elevation are not modified.

### Fact B: Vendor Architecture Support Lifecycle
Separately and independently from permissions, NVIDIA Nsight Compute documentation for the installed 2025.1-era toolchain (CUDA 12.x series) explicitly designates Pascal (Compute Capability 6.x) as an **unsupported architecture** for detailed hardware performance profiling and metric collection. NVIDIA transitioned SM 6.x to legacy status, requiring legacy profilers (e.g. `nvprof` / `nvvp` from CUDA 10.x / 11.x) that are incompatible with modern CUDA 12.9 host drivers and modern Linux kernels (6.12+).

---

## 3. Methodological Conclusion
1. Hardware counter collection on Pascal SM 6.1 is not supported within the modern CUDA 12.9 toolchain.
2. In accordance with Section 1 of the research charter, M2 metrics remain strictly grounded in:
   - Nanosecond-precision CUDA event timings (`cudaEventElapsedTime`) with 10 warmup and 100 timed iterations.
   - SASS instruction disassembly verification via `cuobjdump -sass -arch sm_61`.
   - Compiler resource accounting via `ptxas -v` and `cuobjdump --dump-resource-usage`.
   - Authoritative CUDA Occupancy runtime API measurements (`cudaOccupancyMaxActiveBlocksPerMultiprocessor`).
